# Create shipping label opens Ship's label page

Decision: `commerce-ship-label-link-001`, locked on Ronald's answer 11 in the 2026-10-10 grilling (16:11 to 16:40 UTC: a "Create shipping label" button on the order page when Ship is installed and set up; plugins cannot call each other, so it opens Ship's own page) and his 1a at 23:20 UTC for Ship's sign-in (the button carries no pass). The page address, `<ship origin>/stores/<siteId>/orders/<orderId>` with each part URL-encoded, is the one Ship's thread gave for its label page at 23:41 UTC. Built on 0296273 and f6e95ac (Ship item prices) in d146cfc; Node 22.23.2.

- `bin/verify-commerce full` on d146cfc: passed. Typecheck and repo audits clean; unit 528 pass, integration 56 pass, sandbox browser 10 pass, native local-stock 1 pass, Orders browser 1 pass.
- Registry bundle: 127,945 bytes with item prices, 128,286 with the link (+341), leaving 2,786 under 131,072; backend sha256 `d961cad1983384e62f35544b49c969b99c4d86c3dd5ae1d134298cf7e677aee2`.
- Unit (`tests/features/orders/view.test.mjs`): a Processing order with an address shows `{ type: "link", label: "Create shipping label", target: { kind: "external", url }, appearance: "primary" }` first among its actions, before Complete order and Correct address, and the blocks pass EmDash's block validation. Without Ship, without an address, on a Completed order and on the order list there is no link. `tests/features/orders/ship.test.mjs`: the address is Ship's origin (a trailing slash dropped), `/stores/`, the encoded store id, `/orders/` and the encoded order id.
- Installed workerd runtime (`tests/integration/registry-checkout-services.test.mjs`): after a real checkout with Ship in the settings and a store key saved, opening the Processing order shows the link to `https://1.1.1.1/stores/synthetic-site/orders/<encoded order id>` and makes no call to Ship and no trade; once a label from Ship completes the order, its page shows no link. Without `ship` in the settings there is no link; with `ship` and a store key whose Ship pass is refused or wrong, the link shows, since only Ship's page can tell, and nothing calls Ship.

Not covered: Ship's label page is not merged or deployed yet (dinkuskit/ship PR 23 and the page after it), so the link has not opened a real page.
