## Deviations from the locked plan (owner adjudication)

1. Registry credential: the plan records a static publish credential in
   a `release` environment (`release-approver-069`). The supported
   GitHub Actions path stores no Atmosphere credential at all: OIDC
   identifies the workflow and the delegated release service writes the
   record. This PR follows the vendor flow and keeps the merge as the
   only routine gate; the `release` environment is not used.
2. Beta Registry publishing: publishing `x.y.z-beta.N` under a
   separate beta plugin name (`release-beta-flow-066`) needs a beta
   package/profile design that does not exist yet. The Registry
   workflow fails closed on prerelease versions rather than publishing
   a beta under the real slug. Beta demo-store e2e automation and the
   automatic pre-mode exit are later slices.

## Review repair round 1

ClawSweeper reviewed `ad466710` and raised one P1 finding (plus the
owner-gate items below): the generated Registry workflow kept a manual
`workflow_dispatch` entrypoint that could feed a hand-picked package
selector into the OIDC-backed publish job, bypassing the `ci: release`
merge gate. Adjudication: `required_fix`. The dispatch trigger and its
manual plan step are removed, leaving `release.yml` delegation as the
only entrypoint (failed publishes still re-run through the Release
workflow's publish-only mode), and `tests/workflows/release-process.test.mjs`
now pins that invariant. The remaining review items (release App
secrets, dashboard authorization, baseline tag, first-run approval,
merge) are classified `human_gate` and were not performed.
