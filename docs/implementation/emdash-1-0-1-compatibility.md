# EmDash 1.0.1 compatibility migration

This bounded migration keeps Commerce at private version `0.0.0` and updates
its host compatibility to the official `emdash@1.0.1` release.

## Package contract

- Node engine: `>=22.16`; verification used mise Node `22.23.2`.
- `emdash`: `1.0.1`, npm integrity
  `sha512-tD2JluGSDfRS/NhTG4M+KEcQsTOFvEMbQlIaRpePk9bLizOES1QUKx20LAEAv0Mpfhz6knii87TDrJwNr+NvAA==`.
- `@emdash-cms/blocks`: `1.0.1`.
- `@emdash-cms/plugin-types`: `0.5.0`.
- `@emdash-cms/plugin-cli`: `0.13.1`.
- `@emdash-cms/sandbox-workerd`: `0.9.1`.
- `@emdash-cms/plugin-test` was not added because this repository had no
  `emdash/plugin-test-runtime` import or plugin-test fixture to migrate.
- Unrelated direct pins remain unchanged. The lockfile was generated by npm
  from the exact manifest pins.

The official upgrade guide is
https://docs.emdashcms.com/upgrade-to-v1/. Source inspection found no
`experimental.registry`, deprecated capability names, or unsupported
`emdash/plugin-test-runtime` imports. Commerce uses public host/plugin entry
points; no `emdash/internal` import was introduced.

## Renderer seam

The installed 1.0.1 `@emdash-cms/blocks` `ToggleElement` type has
`type`, `action_id`, `label`, optional `description`, and optional
`initial_value`; it still has no `disabled` property or disabled forwarding.
The native 1.0.1 admin has a real gray disabled Manage stock slider with an
adjacent “Coming soon” label by default. Pointer and keyboard attempts leave
it off, and the default state persists across save/reload; the trusted
loopback constructor/runtime/request triple enables only the existing native
local test path. The sandbox/Block Kit renderer cannot express that disabled
control, so it emits a safe “Manage stock — Coming soon” notice instead and
does not emit a misleading live toggle. Server-side admission remains
fail-closed for every host. No Commerce quantity or provider fallback was
added.

The original native browser proof also showed the real host footer
`EmDash 1.0.1`. The two old guest-unavailability images are retained as
historical artifacts but are generic homepage captures, not selected checkout
UI proof; guest behavior is established by the HTTP/storage tests.
